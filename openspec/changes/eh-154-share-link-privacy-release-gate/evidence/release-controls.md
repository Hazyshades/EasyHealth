# EH-154 Frozen Release Controls

**Record status:** Required controls defined; production evidence pending
**Scope:** EH-151 public share boundary, EH-152 owner management, EH-153 export/download adapters, and the durable document-deletion handoff.

The controls below are the minimum release contract. A control cannot be marked pass from source inspection alone. The release record must link an executed route, deployment, database, or capture result for the reviewed build.

| Control area             | Minimum release requirement                                                                                                                                                                                                                   | Required evidence                                                                                             | Blocking failure                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Token entropy and format | `v<token_key_version>.<random>`; random portion from the platform CSPRNG with at least 32 bytes; version is a bounded non-secret selector                                                                                                     | Creation and verifier harness; persistence inspection                                                         | Any lower entropy, unbounded selector, or deterministic token blocks release.                                       |
| Token storage and lookup | HMAC-SHA-256 digest keyed by the selected key version; indexed lookup; no plaintext or unkeyed fallback; stored key version must match selector                                                                                               | Schema/DB inspection and log capture                                                                          | Plaintext, unkeyed digest, key-ring fallback, or selector mismatch blocks release.                                  |
| Key rotation             | New links use current key; previous key accepted only for an approved bounded window; malformed and unknown selectors fail; old links are reissued or revoked before retirement                                                               | Rotation record with key-manager reference/version only; current/previous/unknown/malformed scenario results  | Deleting the active key, an unbounded window, or missing retirement evidence blocks release.                        |
| PIN verifier             | Optional PIN uses a per-share salt and approved slow password hash; PIN is accepted only in the JSON body of `POST /api/share/[token]/pin`                                                                                                    | Route capture and persistence inspection                                                                      | PIN in URL, query, cookie, header, response, or logs blocks release.                                                |
| PIN proof                | At least 32 random bytes; HMAC-SHA-256 with `SHARE_PIN_PROOF_PEPPER`; digest bound to exact share; bounded TTL (`60..3600`, default `900` seconds)                                                                                            | Proof-row inspection and missing/wrong/expired/revoked/cross-share scenarios                                  | Reusable cross-share proof, plaintext proof storage, missing expiry, or unbounded TTL blocks release.               |
| Proof cookie             | `__Host-eh-share-pin`, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, no `Domain`; invalid proof is cleared                                                                                                                               | Set-Cookie capture without recording cookie value                                                             | Any weaker cookie scope or proof value in evidence blocks release.                                                  |
| Report scope             | EH-148 `valid` or `limited` recognized validation envelope; exact materialized report source scope; no client-supplied profile scope                                                                                                          | Two-profile and out-of-scope route/export evidence                                                            | Cross-profile, legacy, invalid, tampered, or out-of-scope bytes block release.                                      |
| Raw-document scope       | Explicit child-document allow-list; active owner/document check; archive and tombstone checks on every request                                                                                                                                | Raw proxy request capture and storage request capture                                                         | Signed storage URL, implicit wildcard scope, or stale authorization blocks release.                                 |
| Expiry and revoke        | Expiry and revocation rechecked before each page, API, PIN, export, and raw-document read; generic failure contract                                                                                                                           | Before/after expiry and immediate-revoke scenarios                                                            | Any post-revoke/post-expiry bytes or distinguishable failure blocks release.                                        |
| Public response policy   | Apply before headers/body: `Cache-Control: no-store, private`; `X-Robots-Tag: noindex, nofollow`; restrictive `Referrer-Policy`; no third-party analytics                                                                                     | Header and browser/network capture for every public subroute                                                  | Missing header, cacheable response, referrer leakage, or analytics request blocks release.                          |
| Trusted ingress          | Public unauthenticated HTTPS listener forwards only through private HTTPS/mTLS leg; app origin private-only; forwarding and `X-EH-Edge-*` headers stripped and overwritten; attestation verified                                              | Reviewed deployment artifact, private-origin probe, valid/missing/malformed/expired/spoofed ingress scenarios | Direct-origin access, header-derived requester identity, or missing peer context blocks release.                    |
| Rate limits              | Service-only Postgres RPC and atomic fixed windows; HMAC-keyed token and requester dimensions; token failures `10/60s`, requester failures `30/60s`; generic `429`; unavailable store/config returns generic `503`; no process-local fallback | Production adapter harness, concurrent counter evidence, outage scenario, cleanup evidence                    | Any local fallback, raw identifier persistence, spoofable requester bucket, or fail-open outage blocks release.     |
| Access events            | Only resolved-share decisions create events: `share_id`, event time, result, resource kind, coarse client class, retention expiry; no token/PIN/proof/cookie/URL/PHI/IP/full UA/storage path                                                  | Captured event payloads and DB rows                                                                           | Secret or PHI-bearing fields, unknown-token share event, or failed write that changes authorization blocks release. |
| Retention                | `SHARE_ACCESS_EVENT_RETENTION_DAYS` in `1..90` (default `30`); UTC expiry; cleanup RPC uses advisory lock and bounded batches; worker continues bounded backlog with retry/backoff and alerting                                               | Deployed value, schedule, lock contention/release, repeated-batch drain, retry and alert evidence             | Missing value, unbounded cleanup, lock leak, or silent backlog blocks release.                                      |
| Export policy            | Only explicitly allowed `pdf`, `csv`, or `json`; export reads EH-148 resolver and verified scope; policy headers precede bytes                                                                                                                | Allowed and denied export scenarios                                                                           | Unapproved format, unrelated source, partial file on denial, or storage path blocks release.                        |
| Deletion handoff         | Committed durable document tombstone/report invalidation/final-purge and owner report-delete transition are available to public reads                                                                                                         | Migration/RPC handoff and tombstone scenario                                                                  | Missing or planning-only handoff blocks release.                                                                    |
| Owner management         | List/revoke/replacement is profile-scoped; list never returns token; replacement uses bounded owner/share-scoped idempotency and one successor                                                                                                | EH-152 API/UI and replacement evidence                                                                        | Cross-profile metadata, duplicate successor, or token in list/errors blocks release.                                |

## Gate rule

1. Any unresolved critical or high finding sets `blocked`.
2. Missing production adapter, reviewed deployment artifact, durable-deletion handoff, or executed scenario evidence is a high blocking finding.
3. Only documented low/medium residual risks with an owner and expiry may set `ready-with-risk`.
4. `ready` requires all mandatory controls passed and no residual risk.
5. The reviewed build, deployment configuration, command log, scenario results, evidence owners, risk owners, and privacy sign-off must be recorded together.
