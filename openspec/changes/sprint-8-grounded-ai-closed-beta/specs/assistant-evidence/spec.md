# assistant-evidence Specification

## ADDED Requirements

### Requirement: Every personal claim maps to an authorized source

The server SHALL validate every personal-data claim against the source catalog assembled for the current request. A source identifier is valid only when it maps to a current profile-owned structured source or semantic chunk and remains within the request filters.

#### Scenario: Valid personal claim

- **WHEN** a generated claim references a source ID returned by profile-scoped retrieval
- **THEN** the claim is retained with a citation containing source type, document ID, and route anchor

#### Scenario: Unknown source ID

- **WHEN** a generated claim references an unknown or malformed source ID
- **THEN** the claim is rejected
- **AND** the response contains an insufficient-evidence limitation

### Requirement: Missing evidence produces a safe fallback

When no eligible source supports a personal question, the assistant SHALL return a concise insufficient-evidence response. It SHALL not fill the gap with a plausible value, source, date, diagnosis, or treatment statement.

#### Scenario: No matching personal record

- **WHEN** structured and semantic retrieval return no eligible source for a personal question
- **THEN** the response says that the available records do not answer the question
- **AND** it may offer a general educational explanation without presenting it as the user's result

### Requirement: Citations open the correct source

Citation payloads SHALL contain an opaque source ID, source kind, document ID, human-readable document label, page or row anchor when available, and a route generated by the server. The route SHALL be checked against the current profile before rendering.

#### Scenario: Page citation

- **WHEN** a semantic source came from page 4 of an active document
- **THEN** the citation opens the owning document at page 4 or an equivalent safe anchor
- **AND** it never opens a document owned by another profile

#### Scenario: Structured observation citation

- **WHEN** a claim uses a laboratory observation
- **THEN** the citation opens the owning document and includes the observation date, value, and unit in the evidence summary

### Requirement: Evidence coverage is measurable

The validator SHALL return evidence coverage metadata containing total personal claims, supported claims, rejected claims, structured source count, semantic source count, and limitation codes. The API SHALL return this metadata without returning raw prompt or model internals.

#### Scenario: Limited answer

- **WHEN** at least one personal claim is rejected or a retrieval tier is unavailable
- **THEN** the response status is `limited`
- **AND** the limitations identify the missing evidence category
