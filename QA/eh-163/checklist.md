## What this checklist covers

This checklist covers the worker-only Mistral OCR path for scanned PDFs and image
inputs, its handoff into the existing document review and Registry 2.0 safety
boundaries, and the preservation of the current result when a replacement
attempt fails. Digital PDFs with a complete text layer must keep the existing
Poppler path. Mistral-origin evidence must remain review-only until a named OCR
release is approved. Real medical documents are out of scope until privacy and
legal gates are evidenced.

## Before you start

- [ ] Use a dedicated test account.
- [ ] Use only synthetic or de-identified documents.
- [ ] Confirm the listed test data has finished processing, unless the check
      intentionally tests processing.
- [ ] Do not enable Mistral for real patient documents.
- [ ] For Mistral-path checks, use the approved regional test configuration and
      a disposable worker secret; never paste the API key into the browser or a
      public environment variable.
- [ ] Keep a synthetic digital PDF with a selectable text layer for the
      regression path and a synthetic scan/image fixture for the OCR path.

## Interface checks

### EH163-UI-01: Digital PDF review remains unchanged

**Precondition:** `EH163-DIGITAL-01` is uploaded through **Upload lab results**
and finishes processing. The document is visible in **Documents**.

1. Open the document in **Documents**.
2. Move through every rendered page.
3. Open the extracted laboratory review panel.
4. Inspect a row whose source page and exact text provenance were generated by
the existing digital-PDF path.

**Expected result:** All pages are present, the document reaches its normal
completed/review state, raw values and units are unchanged, and existing exact
source-region behavior remains available where supported. No second resolver,
verified observation, or Health Profile contribution is created merely because
OCR configuration exists.

### EH163-UI-02: Mistral-origin rows stay in review

**Precondition:** `EH163-REVIEW-01` was produced from synthetic/de-identified
input by the worker with `source_text_origin=mistral_ocr`, and the document is

no row is presented as automatically verified, and no unapproved Mistral-origin

### EH163-UI-03: Failed replacement keeps the prior current result

**Precondition:** `EH163-FAILURE-01` has a prior completed result visible in
**Documents**, and a replacement attempt is configured to fail using synthetic
input only.

1. Open the document in **Documents** and record the prior page count and visible
   extracted result.
2. Start the explicit reprocess/retry action.
3. Wait for the replacement attempt to terminate.
4. Reload the document and inspect its pages and extracted evidence.

**Expected result:** The failed attempt is shown as failed or requiring retry;
the prior current page set and extracted result remain available. No partial
replacement page set, mixed attempt, or page-1-only completed result is shown.

### EH163-UI-04: Image/scan flow is not enabled without the release gate

**Precondition:** `EH163-SCAN-01` or `EH163-IMAGE-01` is available, but the
worker is configured with `MISTRAL_OCR_ENABLED=false` or without an approved
regional Mistral test secret.

1. Upload the synthetic scan/image through **Upload lab results**.
2. Open **Documents** after processing terminates.
3. Inspect the processing status and any extracted review rows.

**Expected result:** The system does not silently publish an incomplete
page-1-only clinical result. If the current environment has no user-facing
OCR-unavailable state, record the interface limitation and attach worker/

## Out of scope or not manually testable yet

- The product has no user-facing control for selecting the OCR provider,
  regional endpoint, failure mode, or release approval. Provider selection,
  request shape, response validation, telemetry, and privacy settings require
  the developer evidence above; testers must not use SQL or browser developer
  tools as a substitute for an available interface.
- Real medical documents, public URLs, Mistral Files/Libraries/Batch, global
  endpoint fallback, and automatic verification of Mistral-origin rows are
  prohibited until the privacy/DPA/ZDR/training and release gates are approved.
- Mistral coarse table boxes are not exact biomarker-row geometry. Page-only
  fallback is the expected behavior when deterministic exact geometry is absent.
- Automatic backfill of existing documents, OCR annotations, resolver changes,
  Health Profile rule changes, and replacement of the downstream extraction
  provider are non-goals.
