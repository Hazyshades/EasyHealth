Evidence

The snapshot calls projectLaboratoryOutcome for reported rows, calls projectHealthProfileLaboratoryInput for score input, then calls the outcome projector again when a null input becomes a score exclusion. EH-142 made the assessment predicate authoritative; the snapshot still reconstructs part of its result.

The existing Resolver and Registry 2.0 remain the authority; the seam only concentrates the consumer decision.

Problem

Admission is authoritative in one predicate, but the snapshot loses the decision and rebuilds it across score, reported-result, and exclusion paths.

Solution

Concentrate laboratory admission, its factual evidence, and its safe exclusion result in one deep module used by the Health Profile read path.

Deletion test

Delete the projection module and every caller must duplicate Resolver, verification, range, and censored-value policy. Complexity reappears; the module earns depth.

Wins

  • • locality: one admission decision
  • • leverage: one gate, many consumers
  • • tests cross one seam
  • • exclusions retain source evidence
Constraint: keep Document list behavior out of this module. Keep the Registry 2.0 hard cutover and existing Resolver outcome vocabulary unchanged.

What is intentional

EH-146 correctly keeps score evidence and assessment lifecycle as separate axes. This candidate does not collapse them. It targets the read projection that combines persisted version, job state, fallback, and legacy payload handling before the page and body-map adapters consume it.

↘

Leakage: one deliberate lifecycle axis is assembled through several caller assumptions.

After · one lifecycle projection

deep module

Assessment lifecycle read projection

current version
job state
legacy payload
fallback status
↓
route + page-ready lifecycle state
score evidence remains separate

The page, dashboard, map, and drawer consume the same lifecycle fact without moving persistence ownership.

Problem

The canonical lifecycle mapper exists, but the route and page still carry fallback/default interpretation while map and drawer infer freshness-specific detail.

Solution

Deepen the lifecycle read projection around the existing mapper and preserve the intentional separation between lifecycle and score evidence.

Deletion test

Delete the projection and each surface must learn persisted-version, job, fallback, and legacy-payload rules again. Locality is lost.

Wins

  • • locality: lifecycle rules converge
  • • leverage: one read fact, many surfaces
  • • tests hit one seam
  • • score evidence stays independent
Non-goal: no realtime loop, scheduler, persistence redesign, or change to EH-146's two-axis contract.

Top recommendation

Start with laboratory assessment admission.

It is the narrowest high-leverage seam: the Resolver decision already exists, but the Health Profile snapshot calls the outcome path twice and rebuilds the explanation when input admission returns null. Deepening it improves locality across scoring, reported results, and exclusions without touching Document list behavior, Registry authority, or the EH-123 persistence contract.
